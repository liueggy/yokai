# 阅读增强节奏实机验证

日期：2026-10-21。设备：HONOR PGT-AN10，Android 16，ARM64；调试包 eu.kanade.tachiyomi.debugYokai。模型：waifu2x，2 倍输出。样本：当前漫画第 1 话，输入 1400×2101，输出 2800×4202。充电状态下的短时探索测试，不能替代长期稳定性测试。

## 结论

未达到“连续阅读时每页增强及时完成”的要求。原图仍能继续阅读，但冷页面增强显著落后；测试界面的局部预览耗时不能代表整页耗时。

| 场景 | 实测 |
| --- | --- |
| 条漫首个冷页面 | 计算 30.710 秒，请求到结果可用 34.364 秒 |
| 条漫后续页面 | 排队 29.944 秒，请求到结果可用 64.924 秒 |
| 已缓存页面 | 读取增强缓存 0.693 秒 |
| 连续条漫滚动 | 5 次滑动后 pending 峰值 9，包含正在计算与等待任务 |
| 从右到左连续翻页 | 3 次滑动后 pending 峰值 6 |
| 翻页积压样本 | 排队 88.106 秒，计算 33.370 秒，请求到可用 124.410 秒，随后 display |

离开屏幕的页面出现 wait_cancelled 后，compute_end 仍在之后发生；取消等待没有同步取消共享计算，导致过时任务继续占用串行处理资源。现有分块计算最终仍需完成整页才能展示。

## 短时界面性能样本

| 样本 | 帧数 | janky | P95 | P99 |
| --- | --- | --- | --- | --- |
| 增强开启，条漫滚动 | 698 | 58（8.31%） | 14 ms | 32 ms |
| 增强关闭，反向条漫滚动 | 745 | 40（5.37%） | 11 ms | 23 ms |
| 增强开启，RTL 翻页 | 460 | 10（2.17%） | 7 ms | 22 ms |

开启条漫时 TOTAL PSS 快照 1,003,865 KB；关闭后 842,927 KB。方向、页面缓存、GC、模式和采样时段不同，以上不是严格控制的 A/B，不能将差值全部归因于增强。调试包和 LeakCanary 也会影响结果。

## 优先修复方向
