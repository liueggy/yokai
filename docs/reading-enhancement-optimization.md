# 阅读增强优化与安装验收

日期：2026-10-22。设备：HONOR PGT-AN10 / Android 16 / ARM64。

## 本次优化

- 同一增强请求共享计算，按等待者计数释放；无人等待时取消，在模型分块边界退出。
- 总任务队列上限 3；翻页只处理当前组合页，条漫按可见面积优先逐张处理可见页。
- 350 ms 防抖，滑动过程中维持原图；预加载页面不启动增强。
- 页面重新进入屏幕可重试，增强完成自动调度同屏下一页；超预算页保持原图且不阻塞其他页。
- 限制过期结果显示，回收未显示位图；减少推理输入临时数组。
- 本地 optimized 构建启用 R8/资源压缩，关闭 Debug 和 LeakCanary 调试依赖，补充 ORT JNI 保留规则。
- XNNPACK 试验未显示优势，已移除；保持 CPU 后端与用户选择的模型。

## 已验证的调试构建

增强单元测试 38 项通过，失败 0。调度测试涵盖共享请求释放、无人等待取消、有界队列、分块取消、替代任务身份竞态。

waifu2x，输入 1400×2101，输出 2800×4202：条漫请求到可用 35.329 秒，RTL 翻页 31.349 秒，连续阅读 31.530 秒。同一队列全部样本 pending 最大 1，开始排队约 0～1 ms；原先条漫峰值 9，存在 88 秒排队的样本。离屏取消样本：计算启动 178354252 ms，等待取消 178354588 ms，计算结束 178354999 ms；取消到结束 411 ms，整个被取消计算 747 ms。

左右翻页、上下翻页、条漫、连续阅读均有增强显示记录。LTR 和上下翻页复用同一页面缓存，分别 289 ms、272 ms；不是各模式独立冷处理性能基准。初始 2800×2101 横页超过原有输入预算，保持原图，不能据此宣称所有尺寸都会 AI 增强。所有模式的长期稳定性、所有模型的完整性能矩阵未覆盖。

原始证据：build/device-check/optimized/ 下的 JSONL、gfx、截图；构建日志 build/device-check/optimized-debug-verified.log。旧实测见 reading-pacing-test.md。本轮不同页面和缓存状态不是严格 A/B，不能据差值声称模型计算速度显著提升。整页冷增强仍约半分钟，不保证每页实时完成。

## 本地安装包约定

optimized 为本机可安装的优化构建，沿用 eu.kanade.tachiyomi.debugYokai 包名及本机 debug 签名以保留当前测试应用的数据，桌面名称 Yōkai 增强版。原有 eu.kanade.tachiyomi.yokai 不替换。该签名不是上游官方发布签名；不上传 GitHub 或商店。

离线构建可通过 -PlocalCentralRepository 指定本地 Maven 依赖缓存；默认项目仓库配置不变。本机受限依赖从 Maven 镜像取得，可用 Gradle module 元数据的 SHA-256 做了匹配；构建使用原有依赖版本。
